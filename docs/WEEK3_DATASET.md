# Week 3 dataset: synthetic wellness engagement

- **Source:** generated by `backend/ml/dataset.py` with a seeded numpy RNG (seed 42, 2000 rows). Output: `backend/ml/data/wellness_engagement.csv`. No real people, no patient data, no scraped data.
- **License:** synthetic, created for this project; released under the same license as the repo (free to reuse for education).
- **Label:** `engaged_next_30d` (1 = fictional member uses the wellness app in the next 30 days). Produced by a hidden fictional logistic rule plus Gaussian noise. Positive rate is about 50 percent.

| Feature | Type | Range |
|---|---|---|
| age | int | 18 to 85 |
| sessions_last_30d | int | 0 to 30 (Poisson, mean 6) |
| avg_session_minutes | float | 1 to 120 |
| days_since_signup | int | 1 to 999 |
| reminders_opt_in | 0/1 | about 55 percent opt in |
| preferred_channel | category | email, sms, app |

## Preprocessing / EDA
`python -m scripts.train_ml` prints and stores an EDA summary (row count, positive rate, missing values, numeric describe) in `backend/ml/artifacts/metrics.json` under `eda`. There are no missing values by construction. Numeric features are standardized and the channel is one hot encoded inside the pipeline.

## Limitations
- The label is produced by a known synthetic rule, so metrics say nothing about real member behaviour.
- No health or clinical fields are included on purpose. Age is used only as a generic numeric feature, never to infer health status.
- Not suitable for any real decision about a person.
